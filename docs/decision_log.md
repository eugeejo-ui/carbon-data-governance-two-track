# 결정 기록

- 이 레포의 방향을 정한 결정과, 그 전에 검토하고 기각한 고객 후보군을 기록함
- 기각 이력의 사실은 2026.9.28 조사 기준이며, 이후 재검증 범위 밖임

## 1. 주요 결정

| 시점 | 결정 | 이유 | 관련 위치 |
|---|---|---|---|
| 2026-09 | 판매 제품을 탄소 데이터 거버넌스(watsonx.data intelligence)로 정의 | 계산(3층)은 신정원 공동 플랫폼·탄소 스타트업이 이미 채우고, 출처·품질·변경 이력 관리(2층)가 비어 있음 | 계획서 2장 |
| 2026-09-29 | 제조·금융을 투트랙으로 진행하고 연도별 사다리(제조 → 금융)는 폐기 | 판매 목적 포트폴리오이며, 두 시장의 수요는 각자의 규제에서 나옴 | 계획서 3장 |
| 2026-09-29 | 대상 확대: 제조 트랙에 대기업·외국계 대기업 계열, 금융 트랙에 증권·보험·종속 금융회사 | 규제 대상 전체를 보되, 약점은 점수(⑤ 그룹 IT 계열사 0점)와 표시 항목(대형 고객 조직 담당 가능성)으로 드러냄 | 계획서 7-2 |
| 2026-09-29 | 새 레포로 시작하고 이름은 carbon 유지 | 제품·고객·방법·자료가 대부분 바뀜. 두 규제가 증명할 숫자가 온실가스 배출량이고 KSSB 의무 범위가 기후임 | 계획서 1장 |

- 참고: 대기업 포함은 아래 기각 이력 8번(하류 대형: 자체 개발·동기 약함)과 일부 겹침. 점수표의 ⑤와 표시 항목으로 그 약점을 드러내는 방식으로 처리함

## 2. 기각한 고객 후보군

### 2-1. 이전 프로젝트·논의에서 기각

| 번호 | 후보군 | 기각 이유 |
|---|---|---|
| 1 | 중견 CBAM 제조사에 데이터 층 직접 판매 (cbam-mfg-data-layer-entry) | 먼저 움직여야 할 회사일수록 IT 예산이 작음 (1차 대상 중견 IT 투자 중앙값 14.3억 원, 비대상 33.3억 원). 정부·벤더 경쟁, 동기 약함 |
| 2 | 전기요금 절감 입구 사다리 (mfg-energy-entry-ladder v6) | 전력 예측·설비별 계측·CBAM 데이터 층이 정부 무상 FEMS 구축, 한전 무료 전력 데이터, 수요반응, 기존 벤더로 이미 채워짐 |
| 3 | EMS 설치업체와 협력 | 경쟁 벤더, 자체 개발, 예산 |
| 4 | 공공 허브 (정부 산단 MRV 등) | 경쟁 벤더, 자체 개발, 예산(단가) |
| 5 | CBAM 검증기관 | 경쟁 벤더 |
| 6 | SAP 생태계 | 경쟁 벤더 |
| 7 | 조업 일정 최적화 (CPLEX) | 경쟁 벤더 (대형 APS 자체 엔진, 무료 최적화 도구) |
| 8 | 하류 대형 (2028 확대 대상 대기업) | 자체 개발, 동기 약함 |
| 9 | 하류 협력사 | 예산 |
| 10 | 금융 (초기 검토) | 자체 개발, 정부 경쟁, 동기 약함 → 이후 금융배출량 입력 품질로 좁혀 재채택 (2-2의 금융배출량 항목) |
| 11 | 유통 | 정부 경쟁 |

- 구조적 결론: 규제 때문에 억지로 쓰는 돈은 정부·공공이 흡수함. 노릴 곳은 "IBM이 더 잘하는 곳"이 아니라 "아직 비어 있는 곳" 또는 "이미 IBM을 쓰는 고객에 붙이기 쉬운 곳"임
- 1번의 IT 투자 중앙값은 cbam 레포 결론값(14.3억 원)으로 적음. 이전 논의에 나온 8.9억 원은 이전 레포에서 좁은 정의라 폐기한 값임

### 2-2. 은행·제조 연결 계열에서 기각

| 후보군 | 기각 이유 |
|---|---|
| 대기업 IT 계열사 플랫폼에 부품으로 공급 | 부품 자리를 국산 스타트업·경쟁 벤더가 이미 차지함. 그룹 IT 계열사는 자체 개발 경향. 부품 판매는 건당 금액이 작음 |
| 은행-제조 연결 플랫폼 (교차 할인, 심사 즉시 피드백) | IBM 본사가 이미 시도해 종료함(we.trade 2022, TradeLens 2023, 원인은 참여자 모으기). 남은 무역 플랫폼은 Data & AI 소관이 아님. SAP Taulia·KTNET·은행 자체 할인과 경쟁 |
| 은행-제조 불일치 자리에 부품 공급 (무역서류 심사, 공급망 금융, 전환금융 실적 확인, CBAM 배출량 전달) | KTNET·은행 자체 서비스, SAP Taulia, 신정원 포털, EU 등록부가 이미 채움 |
| 은행이 사서 제조사에 무료로 주는 기업 서비스 | 은행이 직접 만듦. 돈은 은행에서만 나옴 |
| 은행 문서 판독 부품 (trade-doc 확장) | 2026년 은행 AI 구매는 국산·소버린 또는 MS로 채워지는 중. trade-doc 자체는 별도 프로젝트로 유지 |
| 공장 가동 데이터를 은행 여신에 연결 | 은행이 원하는 데이터가 얇음(위치·진동·가동 여부). 연결은 IoT 업체 몫 |
| 금융배출량 시장 전체를 가져가는 방식 | 신정원 공동 플랫폼이 계산을 표준화함 → 플랫폼이 안 하는 입력 품질·출처 증명만 노리는 쪽으로 수정 |
| ESG 연결 공시 종속회사 약 3,014곳 | 대부분 전기·연료 사용량 수준이라 데이터가 가벼움. 돈 내는 주체가 불명확함 |
| CBAM 관련 중소기업 약 1,000곳 | 예산이 IBM 직접 판매 규모와 맞지 않음. 정부 지원사업 대상임 |

## 3. 최종안이 반복된 기각 이유를 피하는 방법

| 반복된 기각 이유 | 최종안의 대응 |
|---|---|
| 이미 채워진 자리 (벤더·스타트업·자체 개발) | 비어 있는 거버넌스(2층)만 팖. 계산은 신정원·스타트업에 맡김 |
| 정부·공공이 흡수 | 공공 플랫폼이 목표로 하지 않는 입력 품질·출처 증명만 노림 |
| 예산 부족 | 제조는 ④ IT 예산으로 거름. 금융은 예산 충분 |
| 동기 약함 | 검증·공시 마감(2027.9 CBAM 신고, 2030 인증, 2031 Scope 3)을 연락 시기로 씀 |
| 소관 범위 | Data & AI 소관이 확실한 watsonx.data intelligence로 한정함 |

## 4. 제조 트랙 연계 프레이밍과 기각 후보의 차이 (v1.3)

- 기각한 은행·제조 연결 후보들은 IBM이 은행과 제조사를 잇는 플랫폼을 만들거나, 은행에 팔아 제조사에 나눠 주는 구조였음
- 연계 프레이밍은 제조사가 거버넌스 제품을 사고, 그 결과 데이터를 은행 서류·대출 심사에 쓰는 구조임
- 은행 쪽 적합성 판단·사후관리는 신정원 기후금융 웹포털이 맡으므로, 우리 몫은 제조사 쪽 증빙의 신뢰성으로 한정함
- 은행이 제조사 자료를 실제 심사에 반영하는지는 H5(계획서 6장)로 검증함
