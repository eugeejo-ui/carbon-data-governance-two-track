**운영 규칙 [확정]**

- 클로드 코드는 동시에 1개만 실행함 — 같은 폴더에서 두 도구가 동시에 작업해 .git이 사라진 사례가 있음(00 문서 5-3)
- 클로드 코드는 사용자 PC의 레포 폴더(C:\carbon-data-governance_two_track)에서 실행하는 것을 전제로 함
- 대화 개시 시점: 대화 ②는 2026-10-12 개시함 (사용자 결정 — 09-5 완료 뒤, 지시문 I-05. 열 수 있는 가장 이른 시점은 09-1 완료 후였음 — 7장 18·19번). 대화 ③은 클로드 코드 3회차 전에 엶 (5장)
- 검토 대화: 09-5·10-5 검토는 설계한 대화(①·②)로 돌아가서 수행함. 대화가 길어졌으면 인계 요약을 받아 새 대화로 옮김
- 인계: 인계 필요 여부는 각 대화가 세부 단계를 마칠 때 제안하고 사용자가 결정함. 숫자 기준(대화 횟수 등)은 근거가 없어 두지 않음
- 인계 요약 6항목: ① 현재 세부 단계와 마지막으로 끝난 작업 ② 확정 사항(결정과 이유 — 결정 주체·시각·검토한 선택지·사용자에게 알린 약점 포함, CLAUDE.md 0장) ③ 미결 사항과 담당 ④ 진행 문서 상태(커밋·동기화 여부) ⑤ 다음에 할 일 ⑥ 사용자 확인을 기다리는 사항. 새 대화의 첫 메시지에는 원래 시작 지시문과 인계 요약을 함께 붙임
- 결과 전달 (2026-10-08 추가): 대화가 세부 단계 결과를 컨트롤 타워에 넘길 때도 결정마다 결정 주체·시각·검토한 선택지·사용자에게 알린 약점·이유를 함께 적음. 컨트롤 타워는 결정을 요청하기 전에 진행 문서(4장·변경 이력)에서 이미 사용자가 정한 사항인지 확인함 — 09-1 전달 요약에 결정 경위가 빠져 이미 정한 사항을 다시 묻는 일이 있었음(7장 11번)
- 검토 중 수정 지시: 설계를 바꾸지 않는 수정(오류·누락·형식)은 대화 ①·②가 같은 클로드 코드 세션에 직접 지시하고 변경 이력에 기록함. 설계 자체를 바꿔야 하면 진행 문서를 고치고 컨트롤 타워에 보고함
- 컨트롤 타워 역할 (사용자 지시 — 2026-10-13부터 대화 ② 전달문 머리에 붙임): 기준·값·범위의 결정은 사용자가 함. 컨트롤 타워는 제안·검토만 하며 기준값·범위·숫자를 스스로 정하지 않음. 제안은 대화 ②가 검토해 사용자에게 올리고 사용자가 정함. 08 반영은 사용자 확정 값을 그대로 옮기는 일이며, 반영 중 새 기준·값이 필요해 보이면 정하지 않고 제안으로 회신함

### 4-7. H4 판정 세부 기준 [확정] (시험 전 고정, 2026-10-07)

- 근거 기준: 계획서 6-2·07 문서 4-1 — 채택(주요 구간 자동 추적 확인) / 부분 채택(SQL·ETL 구간만 추적, 결론에 추적 가능 범위 조건을 붙임) / 기각(주요 구간 추적 불가, 주장을 카탈로그·품질로 축소)
- 아래는 이 기준을 시연 결과에 적용하는 방법이며, 기준 자체를 바꾸지 않음
- 판정 대상은 wdi임. 보조 제품의 결과는 판정에 넣지 않음

**주요 구간 정의**

- 계획서 6-1의 H4 문장("두 트랙의 데이터 흐름(원천 → 계산 → 공시)을 추적할 수 있음")의 세 구간을 주요 구간으로 정함

| 구간 | 내용 |
|---|---|
| ① 원천 읽기 | DB·엑셀·CSV 원천을 읽어 들이는 구간 |
| ② 계산 | SQL·Python 또는 처리 도구로 배출량·품질 점수를 계산하는 구간 |
| ③ 결과 전달 | 제조 결과를 은행 장부·공시용 표로 넘기는 구간 |

**구간 상태 기록**

| 상태 | 뜻 |
|---|---|
| 자동 | wdi가 스스로 계보를 그림 |
| 보완 시 가능 | 주석·OpenLineage·사용자 정의 매핑(00 문서 5-2)으로 이어짐. 보완 방법과 작업량을 함께 기록함 |
| 불가 | 보완해도 이어지지 않음 |

**결과별 판정**

| 결과 | 판정 | 결론에 붙는 조건 |
|---|---|---|
| 세 구간 모두 자동 | 채택 | 없음 |
| 일부 구간이 "보완 시 가능" | 부분 채택 | 구간별 보완 방법·작업량 |
| 일부 구간이 "불가"이고 다른 구간은 자동 | 부분 채택 | 추적 가능 범위 제한 |
| 자동으로 이어지는 구간이 하나도 없음 (SQL 구간 포함) | 기각 | 주장을 카탈로그·품질로 축소 (07 4-1 기각 시 결론) |

- 실패는 "불가"만을 뜻함. "보완 시 가능"은 실패가 아니라 도입 작업 범위로 기록함

**엑셀 구간 시험 범위 [확정] (사용자 결정 2026-10-12 17:01)**

- 제조 시연의 엑셀 원천은 계수 표 1개(EU 기본값·정부 계수·가산 비율 — 한 번 정하면 잘 바뀌지 않는 값의 표, 4-6 제조 원천 배치)임

- 경위: 09-4 결정 36의 약점("엑셀이 계수 표 하나라 현장 엑셀을 읽는 상황은 시험하지 못함")을 컨트롤 타워가 09-4 완료 보고 점검 중 짚음 → 사용자 결정
