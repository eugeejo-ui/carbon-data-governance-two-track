**운영 규칙 [확정]**

- 클로드 코드는 동시에 1개만 실행함 — 같은 폴더에서 두 도구가 동시에 작업해 .git이 사라진 사례가 있음(00 문서 5-3)
- 클로드 코드는 사용자 PC의 레포 폴더(C:\carbon-data-governance_two_track)에서 실행하는 것을 전제로 함
- 대화 개시 시점: 대화 ②는 09-1 완료 후 엶. 대화 ③은 클로드 코드 3회차 전에 엶 (5장)
- 검토 대화: 09-5·10-5 검토는 설계한 대화(①·②)로 돌아가서 수행함. 대화가 길어졌으면 인계 요약을 받아 새 대화로 옮김
- 인계: 인계 필요 여부는 각 대화가 세부 단계를 마칠 때 제안하고 사용자가 결정함. 숫자 기준(대화 횟수 등)은 근거가 없어 두지 않음
- 인계 요약 6항목: ① 현재 세부 단계와 마지막으로 끝난 작업 ② 확정 사항(결정과 이유) ③ 미결 사항과 담당 ④ 진행 문서 상태(커밋·동기화 여부) ⑤ 다음에 할 일 ⑥ 사용자 확인을 기다리는 사항. 새 대화의 첫 메시지에는 원래 시작 지시문과 인계 요약을 함께 붙임
- 검토 중 수정 지시: 설계를 바꾸지 않는 수정(오류·누락·형식)은 대화 ①·②가 같은 클로드 코드 세션에 직접 지시하고 변경 이력에 기록함. 설계 자체를 바꿔야 하면 진행 문서를 고치고 컨트롤 타워에 보고함
- 클로드 코드 보고: CLAUDE.md 10장 보고 항목에 더해, 1~3회차는 data/demo 파일 크기를 보고함 — data/demo는 동기화 범위라 프로젝트 용량에 직접 영향을 줌
- 산출 형식: 1·2회차 산출물은 CSV 파일로 두고, DB 적재는 3회차에서 수행함 — 원천 보관 위치(11-1)가 어느 쪽으로 정해져도 1·2회차를 다시 작업하지 않음

### 2-4. 공통 원칙 [확정]

- 작업 방식·조사 원칙은 CLAUDE.md 한 곳에 둠. CLAUDE.md는 공개 레포에 올리지 않고(.gitignore), 사용자 PC 레포 폴더(클로드 코드가 자동으로 읽음)와 claude.ai 프로젝트 문서(대화가 읽음) 두 곳에 같은 내용으로 둠. 고칠 때는 두 곳을 함께 고침. 각 대화는 시작 프롬프트에서 CLAUDE.md와 이 문서를 먼저 읽음
- CLAUDE.md 포함 원칙
  - 자료 등급: 공시 원문(DART·KIND) → 정부·감독기관 → 신용평가사 → 회사 공식 → 주요 언론·글로벌 IB. 위키백과·나무위키·취업 정보 사이트·블로그는 사용하지 않음
  - 핀포인트 읽기: 큰 문서는 목차·쪽 번호로 필요한 구간만 읽고, 이미 읽은 구간은 다시 읽지 않음
  - 접속 시험: 대화 시작 시 필요한 외부 사이트 접속 여부를 먼저 확인함. 막힌 사이트는 우회하지 않고 위치 지정 발췌 → 대체 공식 출처 순서로 처리함(2026-10-07 추가)
  - 문서 문체: 개조식 어미, 한자어 서술형, 판정은 채택·부분 채택·기각
