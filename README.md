<summary><b>개요 — 프로젝트 성격·구성·범위</b></summary>

### 프로젝트 성격

- 통계 자료에서 새로운 인사이트를 발견·도출하는 탐색형 분석이 아님
- 확정된 규제 일정과 공개 자료를 기준으로, 최적의 접촉 시기와 규모를 갖춘 기업을 선별하는 작업임
- 진행 순서: 고객 과제를 숫자로 찾음 → 그 숫자로 누구부터 접촉할지 정함 → 기업별 데이터의 특수성에 맞는 IBM 제품을 연결함
- 따라서 판단의 무게는 데이터의 양이 아닌 선별 기준의 타당성과 근거의 추적 가능성에 있음

### 구성

- 문제 정의 → 분석 → 실행 → 성과 순서로 구성함
- Ⅰ 문제 정의: 은행을 최초 고객사로 선정한 근거와, 은행이 사용하는 숫자에서 비어 있는 부분
- Ⅱ 맥락(분석): 왜, 언제 수요가 생기는가
- Ⅲ 선별(실행): 누구에게, 언제 가는가
- Ⅳ 결론(성과): 어디에 무엇을 파는가

### 발표 범위

- 선행 프로젝트 결과
  - trade-doc-parsing-model-eval: 최초 고객사와 대상 업무의 선정 근거, 판독 모델 성능 비교 결과 — Ⅰ-2·Ⅰ-3
  - cbam-mfg-data-layer-entry: CBAM 품목 판정 결과, IT 투자 여력 기준(CBAM 1차 적용 중견 IT 투자 중앙값) — Ⅰ-4·Ⅲ-1
  - mfg-energy-entry-ladder(중단): 제조 중견 73곳 명단, 경쟁 대안 분석 방식 — Ⅰ-4·Ⅲ-1
- 진행 문서 00\~07(분석 단계): 대상 선별·채점·연도별 로드맵 — Ⅱ·Ⅲ부

## 🔑 Ⅰ 문제 정의 — 왜 은행이며, 무엇이 비어 있는가

<p align="center"><img src="figures/presentation/part1_problem.png" width="100%" alt="Ⅰ 문제 정의"></p>

<details>
<summary><b>Ⅰ-1. 왜 금융 고객인가 — IBM 소프트웨어의 기존 고객 기반</b></summary>

### Ⅰ-1.1 판매 영역 — 소프트웨어

- IBM 2025년 매출 675.4억 달러 중 소프트웨어 부문이 299.6억 달러(44%)이며, 부문 이익 합계 163.6억 달러 중 99.2억 달러(61%)를 차지함
- 소프트웨어 매출은 전년 대비 10.6% 증가했으며 부문 이익률은 33.1%임 → 성장과 이익을 함께 주도하는 소프트웨어 부문을 판매 영역으로 정함

### Ⅰ-1.2 고객 — 금융권

- IBM 공식 자료: 세계 50대 은행 중 43곳, 10대 결제회사 중 8곳이 IBM 메인프레임을 핵심 플랫폼으로 사용함 (IBM Institute for Business Value 보고서 인용, 2026-09-03 갱신)
- 국내 거래: 국민은행 메인프레임 계약 2030년까지 갱신(2024-12) · 메리츠증권 핵심 거래 시스템 IBM 파워11 도입(2026-03) · 하나캐피탈 재해복구 스토리지(2024-04) · 롯데카드 파워10(2023-04)
- 본 레포 기록: 금융회사 278곳 중 IBM 거래 이력 점수 1점 이상 75곳 — 자체 계약 16곳(최근 5년 공개 계약 4곳 포함), 같은 보고 단위 계열사의 계약 59곳
- 금융회사는 민감 데이터의 외부 반출을 제한함 — 한국은 망분리·데이터 민감도·규제 승인 부담이 내재화 범위를 결정하며, 금융회사 80%(아시아태평양 87%)가 AI 공급사 선정 시 출신 국가를 고려함 (딜로이트, 2026-09) → 은행 내부에 설치하는 소프트웨어 수요가 존재함
- 선정 사유: 금융권은 IBM의 전통적 핵심 고객층이며, 기존 거래 관계를 진입 경로로 활용하기 위해 최초 고객사로 은행을 선정함

### Ⅰ-1.3 불리한 근거

- 국내 기존 관계는 인프라(메인프레임·서버·스토리지) 중심이며, 데이터·AI 공개 사례는 2022년 국민은행 개발 지원 1건이고 거버넌스 제품 계약은 없음
- 국내 시중은행 대부분이 메인프레임을 떠남

</details>

<details>
<summary><b>Ⅰ-2. 왜 은행의 수출서류 심사인가 — 제조사가 쓰고 은행이 판단하는 업무</b></summary>

### Ⅰ-2.1 업무 구조

- 신용장은 개설은행이 일치하는 서류 제시에 대해 대금 지급을 확약하는 약정이며, 개설은행은 신용장을 발행하는 은행으로 정의됨 (UCP 600 제2조) → 서류 심사의 주체는 은행임
- 수출 제조기업이 상업송장·포장명세서·선하증권을 작성해 제출하고, 은행이 신용장 조건과 대조해 심사함 → 하나의 문서를 사이에 두고 제조업과 금융업이 연결됨
- 구매자는 은행이며, 서류 작성자는 수출 제조기업임
- 판독 모델은 문서 전반에 적용되는 범용 모델이며, 수출서류 심사는 판정 규칙이 국제 규칙으로 명문화되어 성능을 검증할 수 있는 최초 적용 업무로 선정함

### Ⅰ-2.2 은행 심사의 부담

- 신용장 서류의 1차 제출 거절률은 세계 기준 65\~80%로 추정됨 (ICC 은행위원회 기술 자문 브리핑 3호, 2022-06 — 추정치이며 최종 지급 거절률이 아닌 1차 제출 기준)
- 은행은 서류 일치 여부 판단에 제출 다음 날부터 최대 5영업일을 사용함 (UCP 600 제14조 b) → 거절 시 수출 제조기업은 서류를 다시 작성해 제출하며, 재심사에 다시 최대 5영업일이 소요됨
- 일치 여부의 판정 규칙이 UCP 600과 국제표준은행관행으로 명문화되어 있어, 판독 모델의 출력을 평가할 기준이 외부에 존재함

### Ⅰ-2.3 은행 내부 설치 요구

- 출처: 딜로이트 「아시아태평양 금융서비스 산업의 미래」(2026-09)
  - 공급망 재편으로 무역금융·거래은행 수요가 증가함 (13쪽). 한국에도 무역금융 수요가 존재함 (18쪽)
  - 선택적 내재화: 판단 규칙·판단근거 기록은 은행이 보유하고 범용 모델은 외부에서 도입함. 한국은 망분리·데이터 민감도·규제 승인 부담이 내재화 범위를 결정함 (36쪽)
  - 기술주권: 금융회사 80%(아시아태평양 87%)가 AI 공급사 선정 시 출신 국가를 고려함. 보고서는 완전한 독립이 아닌 신뢰할 수 있는 파트너십을 권고함 (39쪽)
  - 실제 사례: KB국민은행의 법인 고객 확인 서류 AI 판독 (42쪽)

**해석**

- 판독 AI 자체 개발은 그룹 IT 조직을 보유한 일부 대형 금융그룹(하나·KB)과 국책은행(기업은행)에 한정됨
- 대형 은행 7곳 중 5곳은 판독 AI를 운영하거나 구축 중임 → 선행 프로젝트가 범위 밖으로 둔 '솔루션 교체' 영역에 해당함

**불리한 근거**

- 신한은행은 외부 상용 모델(OpenAI GPT)을 혁신금융서비스 지정과 금융보안원 보안평가를 거쳐 수출서류 심사에 적용함 → 은행 내부 배포 전제와 다른 사례임
- 우리은행은 국내 SI(삼성SDS)를, 지방은행은 국내 클라우드 사업자(네이버클라우드·KT)를 선택하는 흐름임 → 모델 층 공급은 SI 경유 가능성이 큼
- KB AI-OCR은 부수업무 지정으로 외부 판매가 가능하며 하나금융 리딧은 그룹 외부(포스코인터내셔널)에 판매됨 → 금융그룹 IT 조직도 공급자로 경쟁함
- 비은행 대형 보험사 다수는 국내 문서 AI 업체 솔루션을 운영 중임 → 자체 미구축 금융사 상당수는 빈 시장이 아닌 교체·고도화 시장임
- IBM은 SC그룹과 무역서류 AI를 공동 개발한 이력(2019)이 있으나, 모델 한 층이 아닌 공동 완성 솔루션 형태였음

### Ⅱ-3.1 현황 — 제조사 배출량의 금융배출량 입력

- 금융배출량 = 대출 비율(대출 잔액 ÷ 대출 기업 가치) × 대출 기업 배출량 (PCAF 산식)
  - PCAF(Partnership for Carbon Accounting Financials, 탄소회계금융협의체): 금융회사가 대출·투자한 기업의 배출량 중 자기 몫을 계산하는 국제 표준(금융배출량 산정 표준)을 만드는 금융권 국제 협의체임. 사용한 배출 데이터의 품질을 1등급(검증된 실측)\~5등급(업종 평균 추정)으로 나눔
- 따라서 제조사의 사업장 배출량은 그 제조사에 대출한 금융회사의 금융배출량 입력값이 됨
- CBAM 대상 제조사 94곳 중 76곳이 금융회사 18곳과 직접 대출 거래를 하며, 산업은행 1곳이 58곳과 거래함

![CBAM 대상 제조사와 대출 금융회사의 거래 연결망](figures/fin_fig6_mfg_network.png)

### Ⅱ-3.2 현황 — 제조사와 은행 사이의 탄소 데이터 요구 경로

- 요구 경로 8개: 시행 3 · 예정·정부 최종안 3 · 검토·미정 2
- 제조사는 같은 탄소 데이터를 EU 수입자(CBAM 신고)·정부(배출량 명세서)·ESG 공시·원청 고객사·은행(대출 심사) 5곳에 제출함
- 판매 우선순위 상위 제조사 35곳(Ⅲ-1 채점 결과 94곳 중 상위 37%) 중 32곳(91%)이 정책금융기관 3곳(산업은행·수출입은행·기업은행)과 거래함

![제조사와 은행 사이 탄소 데이터 요구 경로의 확대](figures/presentation/16_bank_data_demand.png)

<p align="center"><sub>제조사의 탄소 숫자는 은행 금융배출량의 입력값이 되며, 요구 경로는 8개로 확대됨</sub></p>

### Ⅱ-3.3 가설 검증 — 은행의 검증 가능한 배출 데이터 요구

**① 가설과 판정 기준 (검증 전 확정)**

- 가설: 은행의 녹색·전환금융 심사와 금융배출량 산정은 대출 기업(제조사)에게 검증 가능한 배출 데이터를 요구하거나 우대함
- 판정 기준
  - 채택: 감독 당국 지침 또는 은행 2곳 이상에서 요구·우대가 확인됨
  - 부분 채택: 요구는 존재하나 다른 수단으로 대체할 수 있음
  - 기각: 요구·우대 사례 없음

**② 검증**

- 녹색여신 관리지침 제11조 (금융위원회·환경부·금융감독원, 2024-12)
  - 녹색여신: 정부의 녹색분류체계(K-택소노미)가 친환경으로 인정한 활동(재생에너지 발전·저탄소 설비 전환 등)에 쓰이는 대출임
  - 지침: 은행이 어떤 대출을 녹색여신으로 분류할지 판단하는 기준이며 은행이 자율로 적용함
  - 제11조: 은행은 대출 기업으로부터 녹색 활동에 해당한다는 근거자료를 받아야 함 → 요구 존재
  - 단서: 같은 지침이 적합성 판단은 은행이 대신하고, 환경 피해 배제·사회적 보호 기준은 대출 기업 확인서로 갈음하는 것을 허용함 → 대체 가능
- 전환금융 가이드라인 (2026-02): 대출 기업에게 서약서·전환전략 실행계획 제출을 요구함 → 요구 존재
  - 전환금융: 철강·시멘트처럼 탄소 배출이 많은 기업이 저탄소 공정으로 바꾸는 데 쓰이는 대출·투자임
- 감축 효과별 우대금리 차등: 정부가 추진 중이며 시행 전임 → 우대 미확정
- 은행 상품의 우대 조건: 온실가스 감축량을 금리 조건(성과 지표)으로 쓰는 대출 상품은 기업은행 1곳만 확인됨 → 은행 2곳 이상 기준 미충족

**③ 판정 — 부분 채택**

- 요구는 감독 지침과 가이드라인으로 존재하나 지침이 은행의 대리 판단·확인서 대체를 허용하고, 우대 조건은 은행 1곳과 시행 전 제도에 그치므로 부분 채택으로 판정함
- 결론 반영: 제안 문구를 은행 한 곳에 걸지 않고 "한 번 만든 탄소 데이터를 CBAM 신고·ESG 공시·은행 전환금융 심사에 함께 제출하는 체계"로 정함
- 재판정 조건: 전환금융 실무 모범규준 최종안이 대출 기업 배출 자료의 제출·검증을 의무로 규정하면 채택으로 전환함

### Ⅲ-1.3 가설 검증 — 제조사의 탄소 데이터 근거 관리 층 공백

**① 현황**

- 탄소 데이터 4층 구조 중 수집·산정 층은 정부 공급망 탄소 데이터 스페이스와 국내 탄소 산정 앱이 담당할 예정이며, 근거 관리 층은 공개 자료 범위에서 탄소 전용 공급자가 확인되지 않음 (Ⅱ-4.1)

**② 가설과 판정 기준 (검증 전 확정)**

- 가설: CBAM 1차 업종 제조사 94곳의 과반은 탄소 데이터 근거 관리 층이 비어 있음 — 탄소 데이터 거버넌스 솔루션(출처·변경 이력·품질을 관리하는 도구)의 도입이 공개 자료로 확인되지 않음
- 판정 기준
  - 채택: 도입 미확인 제조사(거버넌스 경쟁 부재 1점 이상)가 과반
  - 부분 채택: 과반이나 합계 점수 상위 3분의 1에서 도입 확정 제조사가 과반
  - 기각: 도입 확정 제조사가 과반

**③ 검증**

- 94곳 각각의 사업보고서 원문과 보도에서 탄소 데이터 거버넌스 도입 근거를 확인함 (거버넌스 경쟁 부재 기준, Ⅲ-1.2)
- 결과: 94곳 중 92곳(97.9%) 도입 미확인 · 합계 점수 상위 3분의 1(31곳) 중 도입 확정 1곳

![제조사의 탄소 데이터 거버넌스 도입 미확인 비율](figures/presentation/08_mfg_hypothesis_gap.png)

<p align="center"><sub>제조사 94곳 중 92곳은 탄소 데이터 근거 관리 층 도입이 공개 자료로 확인되지 않음</sub></p>

**④ 판정 — 채택**

- 도입 미확인 제조사가 과반이며, 상위 3분의 1에서도 도입 확정은 1곳이므로 채택으로 판정함
- 불리한 근거: 공개 자료 범위의 판정이며 비공개 도입은 확인할 수 없음. 공백은 회사 내부의 출처·이력·근거 관리 층으로 한정됨

### Ⅲ-1.4 가설 검증 — 구매 필요성·구매 여력·진입 여지를 동시에 갖춘 제조사의 존재

**① 현황**

- 근거 관리 층 공백은 94곳 중 92곳에서 확인됨 (Ⅲ-1.3)
- 대응이 급한 CBAM 1차 적용 중견 제조사일수록 IT 예산이 작음 (IT 투자 중앙값 14.3억 원, Ⅰ-4.1)

**② 가설과 판정 기준 (검증 전 확정)**

- 가설: 살 이유(구매 필요성 — 이중 보고 대조 부담 2점)·살 돈(구매 여력 — IT 투자 여력 1점 이상, 같은 규모군 IT 투자액 상위 3분의 2)·들어갈 자리(진입 여지 — 거버넌스 경쟁 부재 1점 이상)를 모두 갖춘 제조사가 1곳 이상 존재함
- 판정 기준: 채택 — 1곳 이상 / 기각 — 0곳

**③ 검증**

- 채점 기준 3개(이중 보고 대조 부담·IT 투자 여력·거버넌스 경쟁 부재)를 동시에 충족하는 제조사를 94곳에서 집계함
- 결과: 20곳 (중견 14 · 대기업군 6)

**④ 판정 — 채택**

- 동시 충족 제조사가 20곳 존재하므로 채택으로 판정함
- 용도: 존재 확인용이며 우선 계정 선정에는 사용하지 않음 (데이터 분산도·EU 노출이 빠져 있어 적용 시 EU 노출 확인 4곳이 누락되고 EU 노출이 없는 7곳이 포함됨)
- 불리한 근거: IT 투자액은 정보보호 공시 대상 기업에만 존재함. 구축·연동 비용은 확인하지 못함

- 결론 적용 조건: SQL·ETL 중심 흐름은 자동 추적 가능함. 엑셀·Python 중심 산정(중견 제조사 CBAM 산정이 해당될 수 있음)은 주석·OpenLineage 연결로 보완해야 함
- 불리한 근거: 실제 형태 데이터 적용 검증 전임 (시연 진행 중 — Ⅳ-1.2) · Databricks·Snowflake 중심 고객에서는 비교 열위임

### Ⅳ-2.5 판매 구조와 셀링포인트

- 판매 구조: 도입 → 확장 2단계 — 제조 2026\~2027년 도입·2028년 이후 확장, 금융 2029년 도입·2030년 이후 확장 (Essentials → Standard·Premium)
- 셀링포인트: 책임을 대신 지는 도구가 아니라, 책임을 다했음을 증명하는 기록 — 같은 기록을 ESG 공시 면책 요건(2031년 이후)·제3자 인증(2030년 이후)·데이터 사고 시 관리 체계 입증에 사용함
- 정부 플랫폼과의 관계: 산업통상자원부 공급망 탄소 데이터 스페이스는 연결 대상, 신용정보원 금융배출량 플랫폼은 데이터 출처이며 대체·경쟁 대상이 아님 — 플랫폼이 금융회사별 출처 구분·변경 이력·증빙 관리로 확대를 발표하면 재판정함 (Ⅲ-2.3)

### Ⅳ-2.6 결론

- 10곳 모두에 watsonx.data intelligence를 공통 제품으로 제안함 — 판매 대상인 근거 관리 층의 제품임
- 기업별 차이는 데이터의 특수성에서 나옴
  - 원재료 증빙이 신고값을 좌우하는 곳(KG스틸·TCC스틸·삼아알미늄): 공급사 원산지·실제값 증빙의 계보
  - 공장마다 신고 범위가 갈리는 곳(현대비앤지스틸·한일시멘트·태웅): 공장 단위 범위 구분과 이동 기록
  - 은행(중소기업은행·한국산업은행·한국수출입은행·하나은행): 차주별 배출량의 출처와 품질 등급 근거
- 접촉 순서: 2026년 하반기 KG스틸·태웅·현대비앤지스틸·TCC스틸 → 2027년 한일시멘트 → 2029년 중소기업은행·한국산업은행·한국수출입은행·하나은행
- 두 트랙을 잇는 판매 장면: 제조사가 만든 기록을 데이터 상품으로 대출 은행에 전달함(KG스틸 → 하나은행 등) — 같은 기록이 CBAM 신고·ESG 공시·은행 금융배출량에 함께 쓰임
